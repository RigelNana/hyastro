# hyastro Rust 代码规范

本规范约束 hyastro 的公开接口、实现、依赖、数据、测试和发布。目标顺序：正确性、可审计性、可维护性、性能、简洁性。

## 1. 基线

- 使用稳定 Rust 和当前稳定 Edition；工作区必须在 `Cargo.toml` 固定 `rust-version`。
- MSRV 是公开兼容性承诺。提高 MSRV 必须在发布说明中明确，且不得由非必要依赖被动抬升。
- `cargo fmt` 的默认输出是格式基线。只有团队已证明默认设置不足时才增加少量 `rustfmt.toml` 配置。
- 新代码不得带编译警告。CI 对工作区源码启用 Clippy，测试样例中的合理例外必须局部说明。
- 禁止提交生成物、下载的历表、完整星表或机器相关缓存；小型权威测试数据必须记录许可证与来源。

## 2. 模块与工作区

### 2.1 深模块

每个模块只公开调用者完成任务所需的最小接口，把调用顺序、缓存、数值策略和底层库差异留在实现中。

删除测试：如果删除一个模块只会让调用者换成同样复杂的一串底层调用，这个模块过浅；如果删除后复杂性会散落到多个调用者，它具有保留价值。

### 2.2 初始组织

在实现数量尚少时，优先一个公开 `hyastro` crate 和少量内部模块，不为每个名词创建 crate。出现下列真实接缝时才拆 crate：

- FFI/`unsafe` 与纯 Rust 核心隔离；
- 大型或许可特殊的可选依赖；
- `no_std` 核心与文件/系统功能隔离；
- 至少两个可替换后端共享稳定接口；
- 独立版本和独立发布确有需要。

推荐演进形态：

```text
hyastro/             公开门面与领域类型
hyastro-anise/       可选 ANISE 历表、姿态与动态参考系适配器
hyastro-data/        可选数据格式与快照适配器
hyastro-validation/  仅开发使用的 SOFA、NOVAS、CSPICE 差分 oracle
```

这不是必须一次创建的脚手架。只有满足拆分条件时才建立对应 crate。

### 2.3 模块命名

- 模块名优先单数、单词、领域名词：`time`、`frame`、`earth`、`astro`、`event`、`ephem`。
- 不使用 `utils`、`helpers`、`common`、`misc`。代码必须归属于明确领域。
- `mod.rs` 只组织和重导出，不堆放跨领域实现。
- 内部实现按职责命名，不照抄上游库目录导致第二套领域结构。

## 3. 公开接口

### 3.1 公开面原则

- 上游 crate 的类型不得成为稳定公开接口；在适配器处转换为 hyastro 领域类型。
- 默认私有。只有跨模块调用者需要且语义稳定的项才 `pub`。
- 工作区内部共享使用 `pub(crate)`；不得以公开重导出绕过模块所有权。
- 不保留旧别名、兼容 shim 或弃用转发。发生明确重构时迁移全部调用者。
- 不为未来假设设计 trait。一个实现时使用具体类型；第二个真实实现出现后再提炼接缝。

### 3.2 少用自由函数

公开能力优先顺序：

1. 值自身的方法，例如 `angle.sin()`、`state.at(epoch)`；
2. 类型的关联构造器，例如 `Angle::deg(12.0)`；
3. 深工作流对象的方法，例如 `Frames::transform(state, time)`；
4. 后端 trait 的方法，例如 `Ephemeris::state(query)`；
5. 无自然所有者的纯基础运算才使用自由函数。

不得建立与 SOFA/ERFA C 函数一一对应的顶层自由函数集合。专家级低层包装放在适配器内部或明确的 `raw` 模块；`raw` 不由默认门面重导出。

### 3.3 命名

- 名称短，但不得牺牲语义。标准缩写 `UTC`、`TAI`、`CIRS`、`EOP`、`JD` 可以保留。
- 类型使用名词：`Angle`、`Epoch`、`State`、`Rotation`、`Site`、`Catalog`。
- 方法使用动词或领域惯用短语：`parse`、`format`、`convert`、`rotate`、`propagate`、`observe`、`search`。
- 构造器使用 `new`、带单位构造器或 `TryFrom`；不使用 `create`、`make`、`build` 表达同一件事。
- 访问物理值的方法包含单位：`rad()`、`deg()`、`meters()`、`seconds()`。
- 布尔方法使用 `is_`、`has_`、`can_`。
- 集合迭代遵循 `iter`、`iter_mut`、`into_iter`。
- 缩写不自行发明。`position` 不缩成 `pos`，除非是公式附近的局部变量；`declination` 的公开类型可用领域标准 `Dec`。
- `from` 表示无损且不失败，`try_from` 表示可能失败，`as_` 表示廉价借用视图，`to_` 表示可能分配或计算。

### 3.4 标准 trait

适用时实现标准 trait，而不是发明重复方法：

- `From`/`TryFrom`：无损或可验证转换；
- `Add`/`Sub`：维度和语义明确的代数；
- `Display`：面向用户的稳定可读格式；
- `FromStr`：有明确规范的文本解析；
- `Default`：只有一个显然且安全的默认值时；
- `Iterator`/`IntoIterator`：流式结果；
- `Error`：结构化错误链。

浮点领域类型通常不得实现 `Eq` 或 `Ord`。若业务需要总序，使用显式比较键或经验证的非 NaN 包装。

## 4. 强类型设计

### 4.1 角度

- `Angle` 的规范存储使用 `f64` 弧度，单位只存在于构造和读取接口，不以泛型单位扩大类型数量。
- `Ra`、`Dec`、`Lon`、`Lat`、`HourAngle`、`Azimuth`、`Altitude` 等语义包装负责范围和规范化。
- `Angle` 可表达任意有符号角；有范围约束的类型只能经验证或规范化构造。
- 不允许隐式角度单位转换。`Angle::deg(1.0)` 与 `Angle::rad(1.0)` 必须肉眼可辨。
- DMS/HMS 是表示对象或格式策略，不是内部计算单位。

示例接口形态：

```rust
let ra = Ra::hours(5.0, 34.0, 31.94)?;
let dec = Dec::deg(-5.0, 27.0, 0.7)?;
let sep = Sky::new(ra, dec).separation(other);
println!("{:.6} deg", sep.deg());
```

### 4.2 时间

- 使用 `Time<S>` 或等价标记类型编码时间尺度，其中 `S` 是封闭的尺度标记。
- `Date`、`DateTime<S>`、`Time<S>`、`Duration`、`Epoch<S>`、`Julian<S>` 分开。
- 两段式时间内部保持两个分量；不在方法入口或出口无条件相加。
- 不提供缺少数据上下文的万能 `.to::<S>()`。目标类型通过 `Instant::<S>::from_instant` 或 `JulianDate::<S>::from_instant` 请求转换，模型 trait 决定能力是否存在。
- `UTC` 不是均匀连续秒标尺；时长运算需先明确是在物理时间线还是民用标签上。

示例接口形态：

```rust
let tt = Instant::<Tt>::from_instant(utc, &time)?;
let ut1 = JulianDate::<Ut1>::from_instant(utc, &time_with_eop)?;
let cirs_to_tirs = Frames::new(&time_with_eop).at::<Cirs, Tirs, Utc>(utc)?;
```

### 4.3 参考系、原点和状态

- `Vector<F, U>` 表示在完整计算坐标框架 `F` 中、单位维度为 `U` 的自由向量。
- `Point3<F>` 表示计算坐标框架 `F` 下的长度位置；`F` 已绑定参考系统或参考架实现、原点、轴和手性。
- `State<F, S>` 绑定同一计算坐标框架和 `Instant<S>` 历元；框架变换保留 `S`，不得把算法所需的 TT/UT1 输入误作结果历元尺度。
- `Rotation<A, B>` 只改变自由向量和方向的坐标分量；`FrameRotation<A, B, S>` 额外绑定有效历元；`StateTransform<A, B, S>` 还包含平移、时间导数和有效历元。
- 状态变换固定使用 `r_B = R_AB r_A + t_B` 与 `v_B = R_AB v_A + ω_B × (R_AB r_A) + ṫ_B`。`t_B` 是 A 原点相对 B 原点的位置；`ω_B` 满足 `Ṙ_AB R_ABᵀ = [ω_B]×`。
- 静态常见参考系统使用密封标记类型；运行时 SPICE 帧使用经注册表验证的动态标识。
- 动态类型转换为静态类型必须做身份校验并返回 `Result`。
- 不给不同坐标框架或不同历元实现看似自然但物理错误的运算符。

示例接口形态：

```rust
let frames = Frames::new(&time_with_eop);
let tirs: State<Tirs, Utc> = frames.transform(cirs)?;
let local = site.observe(tirs)?;
```

### 4.4 矩阵和四元数

- 矩阵和四元数是 `Rotation<A, B>` 的内部或显式表示。
- 公开接口以“旋转”表达语义，不要求用户选择矩阵或四元数才能转换参考系。
- 从原始数组构造旋转必须验证有限性、正交性和行列式。
- 性能敏感且来源可信的内部构造可以跳过重复验证，但必须由私有 `unsafe` 不变量或私有受检路径保证。
- 四元数始终归一化；插值前统一符号以选择短弧。

### 4.5 单位策略

- 领域接口使用自有透明包装或轻量量类型，不在泛型参数中编码每一种显示单位。
- 编译期区分维度和领域语义，运行时/方法名区分同维度单位。
- 内核规范单位：角为弧度，长度为米或后端明确的规范单位，时间间隔为秒。跨模块必须在类型或方法名上清楚。
- 天文单位、日、儒略年等转换集中在常数/单位模块，不散落数字字面量。
- 不公开 `type Radians = f64` 之类别名；别名不能提供强类型保证。

## 5. 数值实现

### 5.1 浮点规则

- 默认 `f64`。只有数据格式本身为 `f32` 时允许在解析层暂存 `f32`，进入算法前转换并记录精度。
- 所有公开浮点构造器检查 NaN 和无穷；允许无穷有物理意义的类型必须单独设计。
- 不用 `==` 比较计算所得浮点结果，除非验证定义上的精确哨兵或位模式。
- 不建立全局 `EPSILON`。容差按物理量、算法误差和输入尺度定义。
- 使用 `mul_add`、稳定求和、Horner/Chebyshev 和两段式时间等已知稳定方法；不得为“简洁”改写权威算法而损失数值性质。
- 角差使用周期安全算法；极小角距优先向量/`atan2` 形式，避免灾难性消减。

### 5.2 容差

测试和迭代容差必须命名并带单位：

```rust
let angle_tol = Angle::uas(1.0);
let time_tol = Duration::micros(1);
let range_tol = Length::meters(0.001);
```

每个容差必须来自以下至少一项：

- 标准测试向量；
- 上游实现声明；
- 浮点误差分析；
- 输入数据不确定度；
- 产品需求中的精度等级。

不得因测试失败而随意放宽容差。变更容差必须解释误差来源和实际影响。

### 5.3 迭代与事件

- 求根先括区间，后精化；括区间失败与精化不收敛是不同错误。
- 迭代结果包含残差、迭代次数和最终区间。
- 最大迭代次数由算法给出安全默认，并允许受检配置。
- 周期角在扫描阶段连续解包裹；事件去重以时间容差和事件身份共同判断。
- 不以固定步长扫描作为“完整搜索”保证。步长必须由函数变化率、几何界或自适应策略约束。

### 5.4 常数

- 禁止魔法数字。数学公式中的小整数除外。
- 常数项文档包含名称、值、单位、来源、版本和精确/测量属性。
- 采用 IAU 名义值时命名体现 `NOMINAL` 或由版本化常数组承载。
- 会随 EOP、历表或观测更新的值放在数据对象中，不使用 `const`。

## 6. 上游库与适配器

### 6.1 复用原则

- 权威库已有且许可、平台、精度满足需求的算法应复用，不自行重写。
- 复用前核对模型版本、时间/单位约定、线程安全、维护状态、许可证和测试依据。
- 同一能力只选择一个生产内核；其他库可作为差分参考，不在同一路径重复叠加。
- 上游错误码、数组布局和缩写留在适配器内。

### 6.2 适配器职责

适配器必须：

1. 把领域类型转换为上游规范输入；
2. 验证单位、尺度、范围和数组布局；
3. 调用上游实现；
4. 把状态码映射为结构化错误/警告；
5. 把结果转换回领域类型；
6. 附加模型和上游版本元数据；
7. 以权威向量和差分测试验证转换没有改变语义。

适配器不得：

- 自动联网下载数据；
- 隐式选择过期闰秒/EOP；
- 暴露裸指针或上游全局状态；
- 把上游的低层函数表重导出为门面；
- 捕获错误后返回零值或近似值。

### 6.3 FFI 与 `unsafe`

- 纯 Rust 优先；采用 FFI 必须有精度、成熟度或维护成本的明确收益。
- `unsafe` 限于最小适配器模块，并启用 `#![deny(unsafe_op_in_unsafe_fn)]`。
- 每个 `unsafe` 块前写 `SAFETY:` 注释，逐项说明指针、长度、对齐、生命周期、别名、初始化和线程安全不变量。
- C 结构体布局使用 `#[repr(C)]`，不得假定 Rust 默认布局。
- FFI 输出缓冲先按上游契约初始化；不得读取未初始化内存。
- 上游含全局可变状态时，用进程级锁或隔离实例封装，并在接口文档说明并发特性。
- FFI 适配器必须在 sanitizer/Miri 可覆盖的 Rust 部分运行检查，并对解析/边界层做 fuzz。

## 7. 错误与诊断

### 7.1 错误类型

- 库代码返回具体错误枚举；应用层才使用类型擦除错误。
- 一个深模块一个顶层错误类型，必要时用 `#[source]` 保留底层原因。
- 错误变体包含调用者可行动的信息：字段、值、允许范围、时间覆盖、目标、后端。
- 不用字符串匹配区分错误。
- 调用者显式选择的近似模型或外推策略必须验证适用范围，超出范围返回具体错误。

建议分类：

```rust
pub enum Error {
    Range(RangeError),
    Time(TimeError),
    Coverage(CoverageError),
    Frame(FrameError),
    Ephemeris(EphemerisError),
    Convergence(ConvergenceError),
    Format(FormatError),
    Backend(BackendError),
}
```

### 7.2 模型适用范围

- 上游 SOFA/ERFA 的“可疑年份”等状态转换为具体范围错误。
- 预报 EOP、经验 Delta T 和外推算法只能通过命名入口或显式策略选择。
- 折射低高度、缺失径向速度和覆盖边缘必须返回具体错误或使用语义不同的独立入口。
- 库默认不打印、不写 stderr；可选 `tracing` 只记录实现诊断，不改变计算结果。

## 8. 数据与 I/O

### 8.1 数据对象

- 闰秒、EOP、历表和星表对象默认不可变，构造完成后可安全共享。
- 数据对象只包含计算所需的数据和覆盖区间。
- 解析与使用分离：解析阶段完整验证，查询热路径不重复做文件结构检查。
- 大文件优先借用、流式读取或内存映射；不得无条件复制。
- IERS 原始记录与计算样本分层：C04/finals2000A 解析结果必须保留产品、质量标记、不确定度和空列；只有字段完整的记录才能进入 `EarthOrientationTable`，不得用零补缺失 EOP。
- 文本解析器属于 `std` 适配层；`no_std` 核心只借用构造完成的样本表。库不得自行下载或静默选择 EOP 数据。

### 8.2 不可信输入

- 任何外部长度、偏移、计数先做 checked arithmetic。
- 解析器有可配置的记录数、字符串长度、段数和分配上限。
- 拒绝越界偏移、重叠损坏记录、非法 UTF-8 要求字段、非有限必填数和不支持版本。
- 解析错误包含文件偏移、记录/行/列或 SPK 段标识。
- 对 BSP、FITS、VOTable、CSV 和 IERS 文本解析器建立 fuzz target。

### 8.3 Serde

- `serde` 是可选特性。
- 无损交换格式写出单位、尺度、参考系、原点、历元和模型。
- `Display` 输出不保证可无损反序列化；无损格式使用明确 schema 版本。
- 不序列化进程内缓存、文件句柄或 FFI 指针。

## 9. 内存与性能

- 小型量类型使用值语义，并在合理时 `#[repr(transparent)]`。
- 热路径不得创建临时 `Vec`、`String`、`Box` 或 trait object。
- 固定维度数据使用数组或专用结构，不为三维向量分配。
- 输入借用优先于克隆；返回拥有数据仅在生命周期或缓存语义要求时。
- 批处理接受切片/迭代器和调用者输出缓冲；同时提供易用的分配型便利层。
- `Arc` 只用于真实共享的大型不可变数据；不把每个小值放入 `Arc`。
- 缓存由上下文拥有，容量和淘汰可控；禁止无法清理的全局缓存。
- 优化前建立基准和分配计数。优化不得改变模型、精度或错误语义。
- SIMD/Rayon 是可选实现细节，标量结果在约定容差内保持一致和确定。

## 10. 并发与异步

- 纯计算和不可变数据类型应自然满足 `Send + Sync`。
- 后端若不线程安全，适配器必须明确串行化，不能不安全地伪造 `Send`/`Sync`。
- 核心查询使用同步接口。文件预取、网络下载不属于核心；上层可以自行异步调度。
- 不为 CPU 计算传播异步函数颜色。
- 并行批处理的输出顺序必须确定，错误必须关联输入索引。

## 11. Feature 规范

- Feature 必须是加法性的；开启更多 feature 不得移除接口或改变既有结果模型。
- 默认 feature 保持最小、纯 Rust、离线；ANISE、大型数据格式、Serde、Rayon 和日志分别 opt-in。ANISE 适配器必须关闭其默认 feature，禁止核心间接启用联网的 `metaload`。
- 平台能力使用 `cfg(target_*)`，用户选择使用 Cargo feature；不得混淆。
- Feature 名称使用依赖或能力名：`std`、`serde`、`rayon`、`anise`、`logging`、`catalog-csv`、`text-parsing`、`geodesy`、`vsop87`、`compression`、`integrity`、`fits`、`votable`、`parquet`、`healpix`、`moc`、`sgp4`、`timezone`。`no_std` 通过 `--no-default-features` 构建，不得设计成关闭 `std` 的 feature。
- 可选依赖使用 `dep:` 绑定，禁止同一能力由多个隐式 feature 共同控制。
- CI 至少验证默认、无默认、全 feature 和关键互斥后端组合。

## 12. 测试规范

### 12.1 测试只保护可观察契约

每个测试必须能因一个可信缺陷而失败。禁止测试源代码文本、私有字段排列、编译器派生实现或无意义的默认值。

测试重点：

- 范围和不变量；
- 单位、尺度、参考系和原点不混用；
- 边界、奇异点和断点；
- 模型选择和优先级；
- 往返与守恒关系；
- 权威样例；
- 真实错误传播；
- 覆盖区间；
- 迭代收敛和漏根风险。

### 12.2 单元测试

- 与实现同文件的 `#[cfg(test)]` 测试只覆盖私有算法不变量和最小边界。
- 测试名描述行为和条件，例如 `utc_accepts_positive_leap_second`。
- 浮点断言必须显示容差和单位。
- 参数化样例使用表驱动，失败信息打印输入和误差。
- 不共享可变全局数据；测试可并行、可重复、与时钟和网络无关。

### 12.3 集成测试

建议按用户工作流组织：

```text
tests/
  time_scales.rs
  earth_orientation.rs
  catalog_place.rs
  spk_ephemeris.rs
  observer_place.rs
  rise_set.rs
  eclipses.rs
```

每个端到端测试固定：

- 数据快照和校验和；
- 时间尺度和历法；
- 参考系、原点和模型；
- 期望值来源；
- 物理单位容差。

### 12.4 权威与差分测试

- SOFA/ERFA 对应算法使用官方验证程序的全部相关向量。
- IERS 模型使用 Conventions 提供的测试数据。
- SPK 使用 NAIF/JPL 内核和 CSPICE 参考结果，覆盖段端点、重叠段和不同中心链。
- Gaia 使用官方数据模型和固定小样本，核验 `μα*`、TCB 历元和相关矩阵。
- NOVAS、SOFA/ERFA 或独立实现可作为差分 oracle，但不得只用与被测实现同源的一份代码证明正确。
- 差分失败先确认双方模型、常数、历表、EOP 和修正集合一致。

### 12.5 性质测试

至少覆盖：

- 角规范化幂等；
- 球面↔笛卡尔往返；
- 旋转复合与逆；
- 时间尺度往返；
- 历法↔日序往返；
- 参考系链分步与合成一致；
- 协方差保持对称和半正定；
- 事件根位于返回区间且满足残差；
- 序列化往返保留全部语义元数据。

生成器必须产生极点、对跖、闰秒、日界、覆盖端点、负年份、零/极小视差和高速度等困难输入。

### 12.6 回归、模糊和性能测试

- 每个缺陷保留最小回归用例，并在测试名或注释中记录问题编号。
- 解析器和 FFI 边界进入 fuzz；语料包含有效最小文件、截断文件、恶意计数和字节序变化。
- 基准固定 CPU 无关的工作量与数据，记录吞吐、延迟和分配；不把微小波动当正确性失败。
- 性能优化必须同时运行正确性差分测试。

## 13. 文档规范

- 每个公开项必须有 rustdoc。
- 类型文档说明：物理含义、单位、范围、不变量、参考系/原点/尺度。
- 方法文档说明：模型、数据依赖、错误、精度/覆盖、分配和复杂度。
- 示例使用真实可运行输入，不使用占位值表达关键语义。
- 术语遵循根目录 `CONTEXT.md`；不得把参考系统写成参考架，把时区写成时间尺度。
- 算法实现旁引用规范章节、论文 DOI、官方源码版本或上游函数；仅引用博客不够。
- 高层教程按任务组织，底层参考按模块组织，避免复制同一事实产生漂移。

## 14. 注释规范

- 注释解释原因、不变量、公式来源和数值陷阱，不复述代码。
- 权威算法的变量名可保留论文符号，但入口和出口转换必须使用清晰领域名。
- 复杂公式注明原始符号与代码变量映射。
- `SAFETY:` 只用于 `unsafe` 证明；`NOTE:` 用于非显然约束；不留下未跟踪的待办注释。
- 删除失效注释和被注释掉的代码；历史由版本控制保存。

## 15. 依赖规范

引入依赖前必须记录：

1. 解决的具体能力；
2. 为什么标准库或已有依赖不能满足；
3. 许可证与分发约束；
4. MSRV、平台、`no_std`、FFI 和构建工具要求；
5. 维护活跃度和发布节奏；
6. 安全记录与 `unsafe` 范围；
7. 默认 feature 和传递依赖；
8. 替换成本与适配器接缝；
9. 精度依据和测试质量。

- 生产依赖锁定 semver 范围；参考源码的 commit 只用于调研和差分，不直接成为不透明构建输入。
- 禁止同时引入多个做同一核心工作的重型依赖，除非一个仅在测试中作为 oracle。
- C/Fortran 构建依赖必须在支持平台 CI 实际编译。
- 许可证文件和归属必须随二进制/源码分发要求处理。

## 16. 版本与兼容性

- 遵守 SemVer。强类型语义变化即使签名不变，也可能是破坏性变更。
- 模型、常数和内置数据更新在变更日志中单列，并给出结果影响。
- 序列化 schema 独立版本化；Rust 类型布局不是持久格式。
- 不承诺内部缓存、矩阵存储顺序或私有模块稳定。
- 公开错误枚举若允许未来增加变体，应标记 `#[non_exhaustive]`。
- Feature 的默认集合变化按用户构建影响评估，不静默引入 FFI 或网络能力。

## 17. 代码审查清单

### 17.1 语义

- 输入和输出是否明确单位、尺度、参考系、原点和历元？
- 是否混淆系统/参考架、几何/视/观测位置、UTC/UT1、角/时角？
- 所选模型及其适用范围是否明确？
- 是否存在静默近似、外推、默认零值或重复修正？

### 17.2 接口

- 能否把自由函数归入一个深模块？
- 是否泄露上游类型或调用顺序？
- 名称是否短而不含糊？
- 标准 trait 是否比自定义方法更合适？
- 错误是否可行动且可机器匹配？

### 17.3 数值与性能

- 公式是否来自一手规范并保持数值稳定形式？
- 容差是否有物理依据和单位？
- 是否稳定处理极点、对跖点、闰秒和覆盖边界？
- 热路径是否有可避免分配、复制、虚调用或重复计算？

### 17.4 安全与数据

- 不可信长度和偏移是否 checked？
- `unsafe` 不变量是否完整证明并有测试？
- FFI 全局状态和线程安全是否封装？
- 数据覆盖是否在使用前完成验证？

### 17.5 测试

- 测试是否保护可观察契约并能抓住可信缺陷？
- 是否有权威向量、独立差分、边界和端到端证明？
- 浮点断言是否使用有依据的物理容差？
- 测试是否离线、确定、并行安全和完整套件安全？
